# Rust Port of the clockify CLI — Design Spec

## Context

The `clockify` CLI (`main.go` plus `internal/`, about 1,500 lines of Go and 37 tests) logs Clockify time entries and prints summaries. The menu bar tray (`tray/`, Swift) and the joe-clock skill (`.agents/skills/joe-clock/SKILL.md`) call the installed binary at `~/.local/bin/clockify`. Rust is the default backend language for personal tools, so the CLI moves to Rust.

## Goal

A Rust `clockify` binary with the same subcommands, flags, output and config sources, so the tray and the skill keep working unchanged. A few issues found while reading the Go code are fixed during the port (listed under Fixes). The Go code is deleted once a side-by-side check shows parity.

## Decisions

| Topic | Decision |
|---|---|
| Parity | Same CLI and output text; fix the issues listed below; no broader cleanup |
| Crate | One crate at the repo root, package `clockify-agent`, binary `clockify`, edition 2024 |
| CLI parsing | clap (derive) |
| HTTP | ureq, blocking, with its JSON feature |
| JSON / TOML | serde, serde_json, toml |
| Time | chrono; VNT stays `FixedOffset` +07:00 |
| Errors | anyhow; printed as `Error: {:#}` so wrapped messages keep the Go chain text |
| Duration jitter | Std `RandomState` hash (clock nanos tick in µs on macOS), no `rand` crate |
| HTTP mocks in tests | mockito (dev-dependency) |
| Branch | `rust-port`, cut from master after the current uncommitted changes are committed |

## Layout

```
Cargo.toml
src/main.rs        clap CLI, run_log, run_summary, parse_log_args, entry_times, resolve_task
src/clockify.rs    API client and types           (internal/clockify)
src/config.rs      layered config, project lookup (internal/config)
src/summary.rs     date ranges, totals            (internal/summary)
src/timeutil.rs    parse and format helpers       (internal/timeutil)
src/trello.rs      card lookup                    (internal/trello)
src/validator.rs   14h cap, overlap               (internal/validator)
```

Public functions keep their Go names in snake_case (`parse_duration`, `has_overlap`, `get_clockify_project_id`, `compute_task_breakdown`). `target/` goes in `.gitignore`.

## CLI

```
clockify log [ARGS]... [--date YYYY-MM-DD] [--dry-run] [--project-id ID] [--task-id ID] [--description TEXT]
clockify summary [PRESET] [--by-task] [--from YYYY-MM-DD] [--to YYYY-MM-DD]
```

- Flags may appear anywhere among the positionals, as today (`clockify log <url> 2h --date 2026-06-27`).
- `"4h ago"` stays one positional.
- Only `--` long flags are accepted.
- `--help` is generated by clap. Its wording differs slightly from the Go usage text. The usage lines and flag descriptions stay the same.
- Runtime errors go to stderr as `Error: <message>` with exit code 1. Usage errors (unknown flag, missing subcommand) come from clap and exit 2.

## Behavior kept from Go

- **Log modes:** A (duration), B (start + end), C (start + duration) and relative (`"4h ago"` + duration). Card and no-card (`--description`) argument detection stays the same, and so do its error messages.
- **Jitter:** a 1–5% increase on parsed durations. Mode B has no jitter.
- **Time math:** input times are in VNT (UTC+7). Times sent to Clockify and printed in dry-run are UTC in RFC 3339 with `Z`.
  - Go sent the relative mode's times with a `+07:00` offset. They now go as UTC: the same instant, written differently.
  - An end time before the start time rolls to the next day.
- **Project lookup:** `--project-id` first, then the board mapping (board id match, then a case-insensitive name substring match, then `default_project_id`).
- **Task:** found by the name `#<card number>` using `page-size=1000`, or created when missing. Fix 5 changes this for dry-run.
- **Validation:**
  - Existing entries come from `user/{id}/time-entries` when `user_id` is set, and from the detailed report otherwise.
  - If that fetch fails, a warning is printed and the entry is created without validation.
  - Overlap uses strict inequality, so entries that touch don't overlap.
  - The 14h cap allows exactly 14h.
  - The conflict label falls back from the task name to the description to `(untitled)`.
- **Output:** the "Would create" and "Created time entry" blocks, the Clockify link, and the "Project total today" line keep the same text.
- **Summary:**
  - Presets: today, yesterday, this-week, last-week, this-month, last-month.
  - Projects and tasks are sorted by name.
  - Running timers, entries without a project, and entries longer than 24h are skipped.
  - Task names fall back from the task to the entry name to the description to `(no task)`.
  - Columns are `%-35s`, with a 40-character `─` rule and a Total line.
- **Config:** layered in this order: RMS Clockify `.env`, then RMS Trello `.env`, then `~/.config/clockify-agent/config.yaml` (TOML), then env vars (`CLOCKIFY_API_KEY`, `CLOCKIFY_WORKSPACE_ID`, `CLOCKIFY_DEFAULT_PROJECT_ID`, `TRELLO_API_KEY`, `TRELLO_TOKEN`).
  - A missing or broken config file is ignored, as Go does.
- **Trello:**
  - `trello-agent meta <url>`: the first line, without its `# ` prefix, is the title.
  - The Trello REST API supplies the board id and board name.
  - When `trello-agent` fails, `trello card <url>` (JSON) is the fallback.
  - The card number comes from the long URL slug, or is the short id.
- **HTTP:** 10 s timeout. A status of 400 or above returns `API error: status N`.

Kept as is, though questionable:
- Overlap errors print the conflicting entry's times in UTC.

## Fixes

1. **`summary --from/--to`.** Go's `ResolveDateRange` returns `XT00:00:00Z` for explicit dates, and `ListEntriesForUser` appends `T00:00:00Z` again. With `user_id` set, the request becomes `start=XT00:00:00ZT00:00:00Z`. Presets sent to the detailed report had the opposite problem: bare dates with no time.
   - `resolve_date_range` now returns bare `YYYY-MM-DD` for every case.
   - Both fetch paths add `T00:00:00Z` and `T23:59:59Z` themselves, as `run_log` already does.
2. **Trello credentials in `ps`.** Go ran `curl` with `key=…&token=…` in its argv, where `ps` showed them. The Trello REST calls now go through ureq. Their results and their errors-ignored behavior stay the same.
3. **Dead code.** Not ported: `Config.Save`, `ListEntries`, `ListEntriesForDate`, `TrelloURL` / `trello_url` and `CardInfo.Status`.
   - `trello_url` in a user's config file is ignored, not rejected: serde skips unknown keys.
4. **Single-dash long flags.** Go accepted `-date`. Only `--date` works now. The skill and the tray only use `--`.
5. **Dry-run side effect.** Go's `--dry-run` with a card URL created the Clockify task when it was missing. Dry-run now only looks the task up.
   - A missing task prints `Task: (would create #<card number>)`.
   - An existing task prints its id, as before.
6. **Card-mode start without a leading zero.** `clockify log <card> 9:00 2h` logged at 00:00: `9:00` failed HH:MM parsing and the start fell back to midnight. When the first time argument after a card is neither relative nor HH:MM, the port returns `invalid arguments`, as no-card mode already does.
7. **Running timer disabled the 14h check.** A running timer's empty end parsed as Go's zero time, so the day's total went hugely negative. `daily_total` and `has_overlap` skip entries whose start or end does not parse.
8. **Empty board id matched a mapping.** With no board id from Trello (missing creds or an API failure), any mapping with an empty `trello_board_id` matched first. The id match now runs only when the card's board id is non-empty.
9. **Summary capped at 50 entries.** `user/{id}/time-entries` had no `page-size`, and the API default is 50. Requests now send `page-size=1000`.

Rust would panic where Go mangled data, so the port also:
- cuts the no-card entry name at 50 characters, not 50 bytes. Go could split a Vietnamese character in two.
- handles non-ASCII input in every parser without slicing inside a character.
- parses number fields as ASCII digits only. Go's `Sscanf` read `5x` as `5`. A calendar-invalid date such as `2026-02-31` is rejected, where Go rolled it into March.
- rejects durations above `i32::MAX` seconds, so later chrono arithmetic can't overflow.

## Tests

- Each module ports its Go tests into an inline `#[cfg(test)] mod tests`.
  - `TestSave` is dropped.
  - `TestListEntriesForDate` becomes a `list_entries_for_user` test that checks the URL's date suffixes.
- Client tests run against a mockito server. Same-module tests set the client's `base_url`.
- New tests cover logic that `main.go` never tested:
  - `parse_log_args(args, description)`: pure mode detection for A, B, C and relative, with and without a card, plus each error message.
  - `entry_times(mode, date, explicit_date, now)`, with an injected `now`:
    - VNT to UTC
    - B rolling past midnight
    - A and relative, with and without an explicit `--date`
  - `resolve_task(client, project_id, card_number, dry_run)`: against mockito, a found task returns its id; a missing task sends a POST outside dry-run and sends no POST in dry-run.
  - clap parsing: flags after positionals, `"4h ago"` as one positional, and an unknown flag rejected.
  - `resolve_date_range` with `--from/--to` returns bare dates (fix 1).
- Jitter stays outside `entry_times`, so the time math tests are deterministic.

## Parity check

Run once before deleting the Go code. The script lives in the session scratchpad and is not committed. It builds both binaries and compares stdout, stderr and exit code, using the real config and only commands that don't write:

- `summary today`, `summary this-week --by-task`, `summary last-month`
- `log --description x --project-id <id> 09:00 11:30 --dry-run`. Mode B has no jitter.
- `log <card-url> 09:00 11:30 --dry-run`, for a card whose `#<number>` task already exists. A missing task would make the Go binary create it.
- Errors: `log` with no args, `log --description x 2x`, `summary nope`

Expected differences:
- `--help` text
- `summary --from/--to`: fixed in Rust. Check that it returns the same entries as the matching preset.
- Any summary whose range holds more than 50 entries (fix 9). The Rust total should be the larger one.

## Cutover

1. Commit the current uncommitted `main.go` and `SKILL.md` changes on master. Branch `rust-port` from there.
2. Build the Rust crate next to the Go code. Pass `cargo test`, then the parity check.
3. Delete `main.go`, `internal/`, `go.mod` and `go.sum`.
4. Makefile:
   - `CLI := target/release/clockify`
   - `build` runs `cargo build --release`
   - `test` runs `cargo test`
   - `install` copies `$(CLI)` to `~/.local/bin/clockify`
   - `check`, `tray-test`, `app` and `uninstall` stay unchanged.
5. `CLAUDE.md`: update the build, test and single-test commands and the architecture list, and rewrite the Patterns section for Rust (inline test modules, ureq, TOML plus env override).
6. `.agents/skills/joe-clock/SKILL.md`: the `go build -o ~/.local/bin/clockify ./main.go` line becomes `make install`. Nothing else in that file changes.
7. Run `make install` and check the installed binary with `clockify summary today`.

## Follow-ups after the port

- **Mode A with `--date` logs on the day before.** Done. `clockify log <card> 2h --date 2026-10-12` ended at the midnight that starts Oct 12, so the entry was 22:00–24:00 on Oct 11, outside the Oct 12 overlap and 14h checks. It now ends at the current VNT time of day on that date, as Mode A does without `--date`. The relative mode (`"4h ago"`) keeps its 00:00 anchor on an explicit `--date`.

## Out of scope

- Hardcoded RMS `.env` paths
- The `config.yaml` file name, which holds TOML
- The VNT-only timezone
- The Swift tray
- `agent/skills/joe-clock/SKILL.md`, an unused copy
